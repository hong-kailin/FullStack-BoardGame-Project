# 第 72 课：梳理 UI 问题清单

## 本课学习目标

- 学会系统性地审查 UI 交互问题，而不是"打地鼠式"修 bug
- 理解问题分类和优先级排序的方法
- 产出一份可执行的问题清单，作为后续课程的 TODO

## 核心概念

### 为什么需要"先列问题再修"？

当前做法：想到一个 bug → 让 AI 改 → 手动验证 → 发现新 bug → 再改...

问题在于：
1. **没有全局视角**：改 A 可能破坏 B，但你不知道 B 的存在
2. **没有优先级**：花时间修了 P2 的问题，P0 的问题还在
3. **没有测试保护**：每次验证都要手动点一遍，效率极低

正确做法：
1. 先完整走一遍流程，把所有问题**一次性全列出来**
2. 分类 + 排优先级
3. 从 P0 开始逐个修复，每修一个跑测试验证

### 问题分类

| 类别 | 说明 | 示例 |
|------|------|------|
| **交互 bug** | 功能行为不符合预期 | 点击空格子触发了选中、按钮该出现时没出现 |
| **流程不顺** | 功能对但操作别扭 | 需要点很多下才能完成一个操作、不知道当前该做什么 |
| **视觉问题** | 布局/颜色/信息展示 | 卡牌太小看不清、颜色区分度不够 |
| **缺失功能** | 应该有的功能没有 | 没有操作提示、没有撤销按钮 |

### 优先级定义

| 级别 | 含义 | 标准 |
|------|------|------|
| **P0** | 阻塞游戏 | 不修就无法正常玩下去 |
| **P1** | 体验差 | 能玩但很别扭，容易误操作 |
| **P2** | 锦上添花 | 不影响核心流程，但修了会更好 |

## 操作步骤

### 1. 启动游戏

```bash
# 终端 1：前端
npm run dev

# 终端 2：后端
npm run server
```

浏览器打开 `http://localhost:5174/`，注册/登录后进入游戏。

### 2. 从头玩一局

按以下流程完整操作一遍，在每个步骤记录问题：

- [ ] 登录/注册流程
- [ ] 查看版图（标记分布、空格）
- [ ] 选中版图格子（单选、多选、取消选中）
- [ ] 拿取标记（1个、2个、3个、含珍珠）
- [ ] 查看金字塔卡牌（费用、奖励、能力）
- [ ] 购买卡牌（买得起的、买不起的）
- [ ] 拿取黄金 + 保留卡牌
- [ ] 购买保留的卡牌
- [ ] 使用特权
- [ ] 补充版图
- [ ] 跳过回合
- [ ] 标记超限归还
- [ ] 皇室卡牌触发和选择
- [ ] 万能奖励颜色选择
- [ ] 查看对手信息（标记、卡牌、保留区）
- [ ] 回合切换（当前玩家标识）
- [ ] 游戏结束（胜利提示）

### 3. 记录问题

用以下格式记录每个问题：

```
### [编号] 问题标题
- **类别**：交互bug / 流程不顺 / 视觉问题 / 缺失功能
- **优先级**：P0 / P1 / P2
- **复现步骤**：1. xxx  2. xxx  3. xxx
- **期望行为**：应该是什么样的
- **实际行为**：现在是什么样的
- **截图/备注**：（可选）
```

## 问题清单

> 以下是在玩的过程中发现的问题，按优先级排列。

### [1] 登录页缺少游戏介绍
- **类别**：缺失功能
- **优先级**：P1
- **复现步骤**：打开页面 → 看到登录表单
- **期望行为**：页面上有游戏名称、简短的游戏说明（璀璨宝石对决是什么、怎么玩），让新玩家知道这是什么
- **实际行为**：只有一个光秃秃的登录/注册表单，没有任何游戏相关信息

### [2] 版图选中顺序限制过严
- **类别**：交互bug
- **优先级**：P1
- **复现步骤**：版图上有 A-B-C 三个连续格子 → 先点 A → 再点 C → 再点 B
- **期望行为**：A、B、C 在同一直线上且相邻，无论点击顺序如何都应该允许选中
- **实际行为**：先点 A 再点 C 时，A→C 方向不满足相邻条件，被拒绝
- **根因**：`validateCellSelection` 把新格子直接 append 到数组末尾，只检查了 `[pos1, pos3]` 的相邻性。应该尝试把新格子插入到所有可能位置，只要存在一种排列满足条件就通过

### [3] 拿取标记时缺少"对手将获得特权"的预警
- **类别**：流程不顺
- **优先级**：P1
- **复现步骤**：选中 3 个同色标记（或 2 个珍珠）→ 点击"拿取标记"
- **期望行为**：在确认拿取前，提示"这样拿取会让对手获得 1 个特权，确定吗？"
- **实际行为**：没有任何预警，玩家拿完才知道对手多了个特权

### [4] 黄金模式提示位置怪异
- **类别**：视觉问题
- **优先级**：P1
- **复现步骤**：选中一个黄金格子 → 点击"拿取黄金并保留卡牌"
- **期望行为**：提示应该出现在操作区域附近（比如金字塔上方），和当前操作上下文关联
- **实际行为**：提示"请选择一张要保留的卡牌"跑到游戏界面最上方，和操作区域分离

### [5] 黄金模式无法取消
- **类别**：缺失功能
- **优先级**：P0
- **复现步骤**：进入黄金模式后 → 想反悔
- **期望行为**：有一个"取消"按钮可以退出黄金模式，回到正常状态
- **实际行为**：没有任何取消途径，必须选一张卡牌才能退出

### [6] 黄金模式下所有卡牌应该高亮
- **类别**：交互bug
- **优先级**：P1
- **复现步骤**：进入黄金模式 → 查看金字塔卡牌
- **期望行为**：保留卡牌不需要支付费用，所有卡牌都应该高亮为可选状态
- **实际行为**：只有买得起的卡牌高亮，买不起的灰显，容易让玩家误以为只能保留买得起的卡牌

### [7] 缺少"保留卡牌仍需购买"的提示
- **类别**：缺失功能
- **优先级**：P1
- **复现步骤**：进入黄金模式 → 准备选卡牌
- **期望行为**：界面上有文字提示"保留的卡牌不会自动获得，之后仍需花费标记购买"
- **实际行为**：没有任何说明，新玩家可能误以为保留 = 直接获得

### [8] 金字塔缺少牌库剩余数量
- **类别**：缺失功能
- **优先级**：P1
- **复现步骤**：查看金字塔 → 想了解每个等级还有多少张卡牌
- **期望行为**：每个等级旁边显示"剩余 X 张"，让玩家知道牌库还有多少
- **实际行为**：只显示翻开的卡牌，不知道牌库还剩多少

### [9] 购买卡牌缺少确认步骤
- **类别**：流程不顺
- **优先级**：P1
- **复现步骤**：点击金字塔中的卡牌 → 直接购买成功
- **期望行为**：点击卡牌后弹出确认提示（显示费用、奖励等信息），玩家确认后再执行购买
- **实际行为**：一点就买，容易误触发，尤其是手机上

### [10] 购买保留卡牌也缺少确认步骤
- **类别**：流程不顺
- **优先级**：P1
- **复现步骤**：点击玩家信息面板中的保留卡牌 → 直接购买成功
- **期望行为**：和金字塔卡牌一样，点击后弹出确认提示再执行购买
- **实际行为**：一点就买，没有确认步骤

### [11] 购买卡牌后剩余卡牌不应平移
- **类别**：交互bug
- **优先级**：P1
- **复现步骤**：金字塔某行有 5 张卡牌 → 购买中间那张 → 新卡牌补进来
- **期望行为**：新卡牌出现在被买走卡牌的原位置，其余卡牌位置不变
- **实际行为**：剩余卡牌向左侧平移填补空位，新卡牌追加到最右侧，视觉上卡牌位置全变了
- **根因**：`removeCardAndRefillPyramid` 用 `filter` 移除卡牌导致后续元素前移，`refillPyramidLevel` 用 `push` 追加到末尾

### [12] 使用特权和补充版图应合并为一个按钮
- **类别**：流程不顺
- **优先级**：P1
- **复现步骤**：玩家有特权时 → 看到"使用特权"和"补充版图"两个独立按钮
- **期望行为**：一个"使用特权"按钮，点击后弹出两个选项：
  - "拿取标记"（版图上无可拿标记时禁用）
  - "补充版图"（袋子为空时禁用）
- **实际行为**：两个独立按钮，看起来像两个不相关的操作，且补充版图没有特权消耗的视觉关联

### [13] 版图上缺少特权标记的显示
- **类别**：缺失功能
- **优先级**：P1
- **复现步骤**：游戏开始 → 查看版图
- **期望行为**：版图上能看到特权标记的位置和数量（初始 2 个），特权被使用/获得时数量实时更新
- **实际行为**：版图只显示宝石标记，特权标记完全不可见，玩家不知道版图上还有几个特权

### [14] 归还标记界面遮挡了游戏状态
- **类别**：流程不顺
- **优先级**：P0
- **复现步骤**：标记超过 10 个 → 触发归还界面
- **期望行为**：归还面板以弹窗/侧栏形式出现，玩家仍能看到金字塔卡牌和自己已购买的卡牌，据此决定归还哪些标记
- **实际行为**：归还面板独占整个界面，金字塔、卡牌、对手信息全部被遮挡，玩家只能盲选

### [15] 页面需要滚动才能看到全部内容
- **类别**：视觉问题
- **优先级**：P0
- **复现步骤**：进入游戏 → 查看页面
- **期望行为**：所有游戏元素（版图、金字塔、玩家信息、操作按钮）适配在一屏内，无需滚动
- **实际行为**：内容超出视口高度，需要拖动滚动条才能看到底部按钮和玩家信息，严重影响游戏体验

### [16] 玩家已购卡牌展示不够清晰
- **类别**：视觉问题
- **优先级**：P1
- **复现步骤**：玩家购买多张卡牌后 → 查看玩家信息面板
- **期望行为**：以表格形式清晰展示每种颜色的统计——该颜色卡牌数量（代替宝石数）、该颜色宝石持有数、该颜色总分，一目了然
- **实际行为**：卡牌按颜色分组排列成小方块，只有点数和王冠信息，缺少宝石代替数和分色的分数汇总

### [17] 🔥 无法快速测试特殊场景
- **类别**：缺失功能
- **优先级**：P0（阻塞后续 UI 测试）
- **复现步骤**：想测试皇室卡牌触发、游戏结束、牌库抽空等场景 → 需要正常玩一整局才能触发
- **期望行为**：有调试/作弊手段可以快速构造特定游戏状态（如直接给玩家加 19 分、加 5 个王冠、清空某个牌库等），方便测试 UI 在各种边界情况下的表现
- **实际行为**：只能正常玩，很多边界场景的 UI 根本没机会验证
- **处理**：下节课优先实现调试工具，然后再继续测试剩余场景
